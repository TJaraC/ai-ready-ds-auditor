    Create README.md at the repository root. Structure and content requirements:

    **Title and tagline:**
    "AI-Ready Design System Auditor" — connect your Figma Design System to Cursor/Trae for free. One line on what it does, one line on who it's for (Non-Enterprise Figma users).

    **What it does (brief — 3-4 bullets):**
    - Plugin audits Figma file for hardcoded colors, typography, spacing, disconnected components
    - Injects structured data into Figma via pluginData
    - Local MCP server exposes it to AI IDEs as three tools
    - No cloud, no subscription, works on free Figma plan

    **Prerequisites section:**
    - Figma Desktop (free plan works)
    - Node.js 18+ installed
    - Cursor IDE or Trae IDE

    **Step 1 — Install the plugin:**
    - Link to Figma Community page (placeholder: "Search 'AI-Ready DS Auditor' in Figma Community")
    - Or: Open Figma → Resources → Plugins → search "AI-Ready DS Auditor"

    **Step 2 — Get a Figma Personal Access Token:**
    - Figma → Account Settings → Personal access tokens → Generate new token
    - Scopes needed: `file_content:read` (read-only)
    - Copy the token — it starts with `figd_`

    **Step 3 — Get your Figma file key:**
    - Open the Figma file in browser
    - URL format: `figma.com/design/XXXXXXXXXXXX/FileName` — the `XXXXXXXXXXXX` part is the file key
    - Or: run the plugin, go to the "AI Context" tab — the File ID is displayed there after injection

    **Step 4 — Run the plugin (audit + inject):**
    - Open your Figma file with the Design System
    - Open the plugin (Resources → Plugins → AI-Ready DS Auditor)
    - Click "Inject / Update" — the plugin scans the file and writes structured data
    - The health dashboard shows total tokens, component count, and audit issues
    - Green checkmark = data injected; orange = out of sync (re-inject after design changes)

    **Step 5 — Build and configure the MCP server:**
    ```bash
    # Clone this repository
    git clone https://github.com/YOUR_USERNAME/ai-ready-ds-auditor.git
    cd ai-ready-ds-auditor

    # Install dependencies and build
    npm install
    npm run build

    # The server entry point is:
    packages/mcp-server/dist/index.js
    ```

    **Step 6 — Configure your IDE:**

    Cursor subsection (`.cursor/mcp.json` or `~/.cursor/mcp.json`):
    ```json
    {
      "mcpServers": {
        "ai-ds-auditor": {
          "command": "node",
          "args": ["/ABSOLUTE/PATH/TO/packages/mcp-server/dist/index.js"],
          "env": {
            "FIGMA_ACCESS_TOKEN": "figd_your_personal_access_token",
            "FIGMA_FILE_KEYS": "YOUR_FIGMA_FILE_KEY"
          }
        }
      }
    }
    ```
    Note: Replace `/ABSOLUTE/PATH/TO/` with the actual full path to your cloned repository (e.g., `/Users/alice/projects/ai-ready-ds-auditor`). Multiple file keys: comma-separated (`"KEY1,KEY2"`).

    Trae subsection (Settings → MCP Servers or `mcp.json`):
    ```json
    {
      "mcpServers": [
        {
          "name": "ai-ds-auditor",
          "command": ["node", "/ABSOLUTE/PATH/TO/packages/mcp-server/dist/index.js"],
          "env": {
            "FIGMA_ACCESS_TOKEN": "figd_your_personal_access_token",
            "FIGMA_FILE_KEYS": "YOUR_FIGMA_FILE_KEY"
          }
        }
      ]
    }
    ```
    Note: Trae uses an array for `mcpServers` and combines command+args in a single array.

    **Available MCP tools section:**

    `get_design_tokens` — Returns design tokens (colors, typography, spacing) formatted for your CSS framework.
    Parameters: `fileKey` (optional — defaults to first configured file), `framework` (optional — "tailwind" | "css-variables" | "css-modules" | "styled-components", defaults to "css-variables")

    Example prompt in IDE: "Show me all the design tokens as Tailwind config"
    → Returns a Tailwind `theme.extend` object with colors, fontSizes, spacing.

    `get_component_specs` — Returns full specification for a component by name or ID.
    Parameters: `componentName` (optional), `componentId` (optional), `fileKey` (optional)

    Example prompt: "What props does the Button component have?"
    → Returns component name, description, variants, and usage notes.

    `get_audit_summary` — Returns audit issues filtered by category.
    Parameters: `fileKey` (optional), `category` (optional — "color" | "typography" | "spacing" | "components")

    Example prompt: "What are the hardcoded color issues in this design system?"
    → Returns list of nodes with hardcoded fills/strokes, including node IDs and suggested fixes.

    **Rate limits section (important):**
    - Free Figma plan: 6 GET /v1/files requests per month per file
    - The MCP server caches data for the session — only one API call per server start per file
    - Keep MCP server sessions running to avoid re-fetching
    - If you hit the monthly limit: the server returns a clear error — wait until the next calendar month or upgrade to Figma Professional

    **Troubleshooting section:**
    - 403 error: Set the Figma file to "Anyone with the link can view" (Share → Change → Anyone with the link)
    - "Out of sync" indicator: Click "Inject / Update" in the plugin after making design changes
    - "No data found": Run "Inject / Update" in the plugin first — the MCP server reads pluginData written by the plugin
    - Token starts fresh each new IDE session: Normal — the in-memory cache is session-scoped

    **Development section (brief):**
    ```bash
    npm run dev        # Watch mode for all packages
    npm run build      # Build all packages
    npm run type-check # TypeScript check (zero errors required)
    npm run lint       # ESLint (zero errors required)
    npm test           # Vitest unit tests
    ```

    Keep the README concise and scannable. Use headers, code blocks, and brief explanations. Do NOT use emojis. Target: a designer-developer who is comfortable with a terminal but not necessarily a TypeScript expert.
